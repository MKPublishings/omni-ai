# Ionirix Eight-Point Hierarchy Constitution

## Article I. Sovereign Order

The Ionirix Eight-Point Hierarchy is the binding structural law for this workspace. Every executable module, template, script, and integration surface must map to one constitutional Point and one or more named features within that Point.

## Article II. Eight Points

1. `P8-sovereign`: Workspace Creation; Memory Engine; Reasoning Modes; Data Ownership
2. `P7-societal`: Persona Modeling; Scenario Simulation; Knowledge Graph; Intelligence Ingestion
3. `P6-legality`: Contract Generator; Compliance Engine; IP Protection; Data Sovereignty Controls
4. `P5-oversight`: MRR Dashboard; Value Flow Mapping; Memory Archive; Feedback Loops
5. `P4-directive`: Positioning Engine; Budget Simulator; Playbook Generator; Roadmap Builder
6. `P3-managerial`: Command Console; Campaign Tracker; Feedback Intake; A/B Test Engine
7. `P2-operational`: Workflow Orchestration; Template Library; Simulation Pipeline; Customer Success Rituals
8. `P1-contact`: Onboarding Flow; Artifact Exporter; Campaign Asset Generator; Unified Intake

## Article III. Structural Law

1. No module exists without a declared Point.
2. No feature ships without constitutional traceability.
3. No direct cross-point import is legal; all cross-point exchange must traverse the hierarchy event bus.
4. No event emission or subscription is legal unless authorized by the hierarchy configuration.
5. No build is compliant unless the validator reports zero critical violations.

## Article IV. Runtime Order

The hierarchy engine initializes the constitution, registers all Points, binds lifecycle hooks, and emits a compliance audit before execution. Runtime execution is valid only after successful registration.

## Article V. Evidence and Auditability

All modules must publish immutable manifests, named feature handlers, and auditable metadata sufficient for the validator to prove compliance.
